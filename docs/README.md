# Project documentation

Start with [the main project tracker](personal-site-plan.md). Its Current status is the handoff for ongoing work; dated entries are history, not competing instructions.

- [Development and documentation rules](development.md): progress, decisions, commits, validation and release records.
- [Release notes](changelog.md): curated shipped changes, not a dump of Git history.
- [Release evidence](release-checks.md): actual checks, deployment links and limitations.
- [Writing and publishing](obsidian-writing.md): the Obsidian/PublishDesk post workflow.
- [Bookshelf operating guide](../_writing/books/README.md): CSV import, automatic covers, curation, related posts, preview, publication and recovery.
- [Bookshelf tracker](books-plan.md) and [release specification](bookshelf-release-spec.md): implementation decisions and safeguards.
- [PublishDesk UI plan](publishdesk-ui-plan.md): record grouping, layout and test evidence.
- [Design foundation](design-foundation.md): the site's visual direction.
- [Independent catalogue](bookshelf-independent-catalogue-spec.md): explicitly deferred future scope; do not implement during the current release.

These are ordinary Markdown files in Git. No AI service is needed to read, maintain or use the project. Repository instructions live in [AGENTS.md](../AGENTS.md); tools that do not discover that file automatically should be pointed to it explicitly.
